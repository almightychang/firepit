# safe cuTile Q8_0 GEMV on RTX 5080 (2026-09-29)

표기: **[확인]** = 실측 또는 코드·SASS로 확인. **[추정]** = 계산이나 간접 근거.

## 요약

- safe cuTile(`unsafe`, `unchecked_accesses`, raw pointer 없음)로 짠 Q8_0 GEMV v1이 B = 1에서 candle `fast_mmvq`와 동급이다. output head에서 peak 960 GB/s의 89%. [확인]
- B > 1에서는 v1이 느려진다. 원인은 register 제한으로 인한 낮은 occupancy다(SM당 8 warp). 계산이 길어진 만큼 떠 있는 메모리 요청이 줄어 DRAM 사용률이 95% → 54%로 떨어진다. [확인: ncu]
- tileiras는 i8 → i32 확장·곱·합 패턴을 `IDP.4A`(dp4a)로 내린다. dp4a는 cuTile 공백이 아니다. [확인: SASS]
- `mma(i8)`는 N = 8에서 tensor core 명령을 내지 않았다. 64×64×64에서는 `IMMA.16832`. [확인: SASS]

## 환경

RTX 5080 (sm_120, peak 960 GB/s — NVIDIA 사양), 호스트 드라이버 580.173.02, `nvidia/cuda:13.3.0-devel` 컨테이너, cutile `=0.4.0`. candle은 compat libcuda가 필요해 두 쪽 모두 compat 드라이버에서 비교했다. 측정은 CUDA event 중앙값, JIT 제외, 반복마다 L2 flush. [확인]

## 변형

설계는 [../../kernels/q8-gemv.md](../../kernels/q8-gemv.md).

| 변형 | 루프 순서 | activation | 내적 |
|---|---|---|---|
| v1 | k 바깥, B축은 tile로 broadcast | f32 | f32 FMA |
| v1b | 세션 바깥, k 안쪽 | f32 | f32 FMA |

- v1b/v2는 가중치를 세션마다 다시 읽는다. 시간이 B에 거의 비례하므로 L2가 흡수하지 못한다. [확인: 수치]
- 작은 shape(27.8 MB)는 850 GB/s 기준 약 33 μs여야 하지만 모든 구현이 43~44 μs다. launch와 파이프라인 가동 시간으로 보이며, GEMV 안에서는 줄일 수 없다. [추정]
- 정확성: v1은 CPU f64 대비 상대 오차 약 7e-6, v2는 같은 양자화의 CPU reference 대비 6.8e-7. x 양자화 자체의 오차는 테스트 입력에서 최대 4.6e-2. candle은 CPU 경로 대비 3.5~4.6e-3. [확인]

## ncu: v1 output head, BN = 64, NB = 8

| | B = 1 | B = 8 |
|---|---:|---:|
| 시간 | 756 μs | 1,350 μs |
| DRAM 사용률 | 95% | 54% |
| 원소당 thread 명령 | 6.5 | 22 |
| issue slot 사용률 | 20% | 37% |
| register / thread | 255 | 253 |
| occupancy 이론 / 실제 | 16.7% / 12.4% | 16.7% / 12.3% |
| local memory (spill) | 0 | 0 |

명령 발행은 포화가 아니다. block당 256 thread × 255 register로 SM당 block 1개만 올라간다. 개선 손잡이는 tile을 줄여 warp를 늘리거나, 다음 chunk load를 미리 거는 것이다(cuTile `occupancy`/`latency` hint). [확인: 수치 / 추정: 손잡이의 효과]

GB10은 대역폭 대비 연산 여유가 5080보다 커서 B 의존성이 작을 수 있다. 확인하지 않았다. [추정]

## cuTile에서 만난 것

| 항목 | 내용 | 상태 |
|---|---|---|
| binary op 타입 불일치 | `reduce` 결과만 generic 기호 대신 구체 shape을 가진다. `binary Mul requires operands of the same type, but got Tile<f32, {[1,16,4]}> and Tile<f32, {[B,BN,NB]}>`. 비교는 `compile_binary_op.rs:337`에서 Rust 구문 타입으로 한다. 우회: reduce 직후 annotated reshape | 알려진 버그 NVlabs/cutile-rs#184 (P0, 2026-07-06 open, 담당 elibol, PR 없음) |
| shape 안의 const 산술 | `{ [BN, BK / 32] }` → `Failed to parse angle bracketed args '<BN,BK / 32>': expected ','`. 32개 block을 축으로 드러내 회피 | 공백 후보, 우선순위 낮음 |
| `ftoi` rounding | `rounding_mode must be nearest_int_to_zero`. 명시적 반올림 계산으로 해결 | 기록만 |
| `trunci` | `missing attribute 'overflow'`. `overflow::NoSignedWrap` 명시로 해결 | 기록만 |
| dp4a | i8 → i32 `exti`·곱·`reduce_sum`이 `IDP.4A.S8.S8`로 내려감 | 공백 아님 |
| int8 MMA | `mma(i8,i8,i32)` [32×32]×[32×8]은 스칼라 `IMAD`/`PRMT`, 64×64×64는 `IMMA.16832.S8.S8.SAT` | 작은 batch에 tensor core는 기대하기 어려움 |

## 재현

측정 당시 코드는 커밋 `f611715`에 있다. 별도 작업 트리에서 해당 커밋을 checkout한 뒤 실행한다.

```bash
git checkout f611715
scripts/dev.sh test
scripts/dev.sh test --release --test gemv_q8 -- --ignored
scripts/dev.sh bench
FIREPIT_CUDA_COMPAT=1 scripts/dev.sh bench
scripts/candle-bench.sh run
```

ncu 실행에는 해당 커밋의 `crates/firepit-kernels/examples/v1_once.rs`를 사용했다(`--cap-add SYS_ADMIN`).
